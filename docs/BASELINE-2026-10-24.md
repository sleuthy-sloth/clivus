```

ctest --preset linux-core --output-on-failure

cmake --preset linux        && cmake --build --preset linux
ctest --preset linux --output-on-failure
```

`linux` and `linux-core` presets were added in this unit; the repo previously had macOS and Windows
only. `linux-core` sets `CLIVUS_BUILD_APP=OFF`, so core work verifies in about a minute.

## Two host fixes required to build at all

1. **DCMTK 3.6 vs 3.7 tag constant.** `core/src/anonymize.cpp` used `DCM_EthnicGroups`, which exists
   in DCMTK 3.7 (what Homebrew ships) but not 3.6.9 (Debian). Replaced with the explicit
   `DcmTagKey(0x0010, 0x2160)`, matching the raw-tag style already used in that array. Same tag,
   no version `#if`.
2. **DCMTK's link interface needs `libtiff-dev`.** Debian's `DCMTKConfig.cmake` links
   `/usr/lib/aarch64-linux-gnu/libtiff.so`, which only `libtiff-dev` provides; without it Ninja
   fails with "missing and no known rule to make it". Host package, not a repo change.

## Not verifiable from here

- GUI rendering, DPI scaling, font behaviour, GPU/driver paths (units 2, 4, 4b, 5).
- `QOpenGLWidget` framebuffer grabs without a display server. Offscreen app tests may need
  `QT_QPA_PLATFORM=offscreen` and software GL; whether they run at all on this host is untested and
  is the first thing to check when the app build is attempted.
- Windows and macOS builds. Windows CI (`windows-app.yml`) remains the only Windows signal.
- Anything about the radiologist's own machine.
